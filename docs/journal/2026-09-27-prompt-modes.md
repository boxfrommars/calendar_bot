# Промпты по режимам и измерения на GPT-6 Luna

[Журнал работ](README.md) · [Первый этап исправлений](2026-09-27-parser-recheck.md)

Дата работы: **27 сентября 2026 года**.

## Задача и условия

После коммита первого этапа `49ea54a` устранены расхождения в названии рабочей
модели и продолжена оптимизация промптов. Владелец подтвердил использование
`gpt-6-luna` локально и в production. Теперь общий default в конфигурации
и evaluation, тесты и контракт размещения согласованы с этим значением.
Файлы секретов и production-инфраструктура не изменялись.

Среда: Windows, Python 3.14.7, OpenAI SDK 2.54.0, Pydantic 2.13.5, Ruff 0.16.8.
Во всех измеренных ответах API указана модель `gpt-6-luna`. Параметры:
`reasoning.effort=low`, `max_output_tokens=3000`, `store=False`.
Responses API, Structured Outputs и web search поддерживаются выбранной моделью
согласно [официальной документации](https://developers.openai.com/api/docs/models/gpt-6-luna).

## Изменения

Общий блок правил дополнен отдельным блоком для текущего режима. Промпт создания
в окончательном варианте побайтно совпадает с `49ea54a`: это проверено сравнением
строк. При редактировании поисковые инструкции заменены коротким порядком
изменения выбранной записи. Дополнительного вызова классификатора нет.
Схема ответа, интерфейс parser, ограничения времени и поиска сохранены.

Evaluation дополнена шестью сценариями редактирования: название, время серии,
напоминания, дата дела, запрет смены типа и добавления записи при правке.
Сравниваются все поля, включая те, которые пользователь менять не просил.
Runner выводит модель и метрики и поддерживает `--report` для технического JSON
без диалогов и ответов модели. Контроль ошибок сохраняет только имя типа,
не текст SDK-исключения. Отсутствующие метрики не заменяются нулями.

тогдашних сценария, включая этот поиск, но не содержал тестов редактирования.
Причина нестабильности поиска в данных отчётах не установлена.

После отдельного разрешения владельца выполнена диагностика с приватной
трассировкой на тех же синтетических данных. Первый одиночный запрос финала
вернул правильные 19:00 UTC и подтверждённый источник. Затем прошли все шесть
веб-сценариев, включая оставшиеся после прежней остановки. Этот отдельный прогон

29,2051 с времени API; лимиты применяются отдельно к каждому `parse`.
Приватный trace не включён в репозиторий. Диагностика не воспроизвела отказ,
поэтому его конкретная причина остаётся неизвестной.

Промпт редактирования короче на **39,9%** по символам; измеренный вход одинакового
запроса смены названия меньше на **28,7%** по токенам. В окончательном варианте
все шесть сценариев редактирования прошли; их API-попытки суммарно заняли 11,5535 с,
использовали 9201 входной и 597 выходных токенов, без веб-поиска.
Для всех этих ответов есть usage; 6945 входных токенов отмечены кешированными.

Метрики относятся к API-попыткам, а не всему пользовательскому диалогу.
`completed_responses` в JSON означает завершение ответа API, а `completed=false`
— незавершённый из-за ошибки проверок набор. Полные суммы между строками таблицы
прогонов несопоставимы, поскольку выполнено разное число сценариев.

Автономный набор: 199 тестов, `OK (skipped=1)` — Linux Unix datagram socket
ожидаемо пропущен на Windows. После окончательного выбора текстов повторно
прошли 49 профильных тестов. Добавлены проверки метрик, отмены, отсутствия
секретов в отчёте и обнаружения незапрошенных изменений при evaluation.
`ruff check`, `ruff format --check`, проверка локальных ссылок и якорей документации
и `git diff --check` прошли.

## Ограничения

Это единичные последовательные прогоны без чередования вариантов и контроля
серверного кеша. Они не доказывают устойчивый выигрыш по задержке, стоимости
или частоте ошибок. В частности, прежний ответ с уточнением короче успешного
ответа с записью. Стоимость в валюте не рассчитывалась.

В окончательном варианте все 29 сценариев успешно проверены в двух отдельных
наборах: 23 основных и редактирования, затем шесть веб-сценариев. Единого
успешного прогона 29/29 нет; в предыдущем полном запуске исторический веб-поиск
вернул уточнение и остановил остальные проверки. Технические отчёты не сохраняют
текст вопроса модели. Приватные трассировки в журнал не включены. Методика запуска и содержание
отчёта описаны в [руководстве разработчика](../development.md#платная-evaluation).
