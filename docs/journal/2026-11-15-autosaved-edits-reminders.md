# Автосохранение правок и интервалы в расписании

## Задача

После изменения интервалов бот показывал черновик, который выглядел как карточка
встречи. Без подтверждения продолжали действовать прежние напоминания. В полном
расписании и утренней сводке действующие интервалы не были видны.

## Условия

Изменение от 15 ноября 2026 года на базе `2854967`. Проверка на Windows с
Python 3.14.8, aiogram 3.31.0, openai 2.54.0 и Pydantic 2.13.5. В тестах
использовались синтетические данные, временная SQLite, управляемые часы и
подставные OpenAI и Telegram API. Схема SQLite и зависимости прежние.

## Изменения

- [Парсер](../../calendar_bot/parser.py) принимает список затронутых полей при
  редактировании. Остальные значения восстанавливаются из выбранной записи.
- [Сервис](../../calendar_bot/service.py) сохраняет правку, очередь и ключ запроса
  в одной транзакции. Повтор обработки возвращает сохранённый результат.
- [Оформление](../../calendar_bot/presentation.py) добавляет интервалы предстоящих
  встреч в полный обзор и сводку. Сводка с уже доставленной частью сохраняет снимок.

## Проверка и результаты

Для встречи в 18:30 по Еревану синтетическая правка «напомни за 1 час и за 30 минут»
сохранилась сразу. Подставная модель вернула другие название, адрес и время вне
списка изменений. В сохранённой записи остались исходные значения. Оба интервала
появились в карточке, расписании и сводке. Работник очереди отправил напоминания
в 17:30 и 18:00 по управляемым часам.

Команды запускались из активного окружения.

```sh
python -m unittest discover -s tests -q
ruff check calendar_bot tests
ruff format --check calendar_bot tests
```

В наборе `unittest` прошли 223 теста из 224. Один Linux-тест сокета systemd
пропущен на Windows. Обе проверки Ruff и проверка относительных ссылок прошли.

## Ограничения

Подписи показывают настройки на момент снимка, в том числе интервалы, время
которых прошло. Проверка новой схемы OpenAI проводилась автономно через SDK.
Живая оценка модели и проверка на сервере остаются отдельными процедурами.
