# Чередующееся сравнение выбора результата

[Журнал работ](README.md) · [Предыдущий эксперимент](2026-09-27-evaluation-repeats.md)

Дата работы: **27 сентября 2026 года**.

## Задача и условия

Проверить одну правку выбора между `items` и `question` для двух ранее нестабильных
сценариев: прямого запроса финала Евро-2024 и продолжения просьбы напомнить
после вопроса о времени. В прошлых трассировках модель либо отказывала из-за
исторической даты, либо сообщала найденные дату, время и пояс, но требовала
дополнительного подтверждения вместо структурированной записи.

По согласованному плану выполнены ровно 20 платных разборов: два сценария,
два варианта промпта, по пять повторов. Условие продолжения — улучшение кандидата
в этом сравнении; только тогда предполагалась полная живая проверка 29 сценариев.

Контроль — `CREATE_INSTRUCTIONS` из `3c2e61c`. Общий блок, редактирование,
перепроверка, схема ответа и параметры API совпадали у обоих вариантов;
равенство неизменяемых блоков проверено до запуска. Модель всех 20 ответов —
`gpt-6-luna`, `reasoning.effort=low`, `max_output_tokens=3000`, `store=False`.
Ограничения каждого `parse` сохранены: 40 секунд, до трёх вызовов инструмента
и одной внутренней перепроверки; автоматические SDK-повторы отключены.

Среда: Windows, Python 3.14.7, OpenAI SDK 2.54.0, Pydantic 2.13.5, Ruff 0.16.8.
Использовались только синтетические данные; приватные трассировки в репозиторий
не включены. Production и пользовательские записи не затрагивались.

## Кандидат

Три строки о продолжении незавершённого добавления заменены следующим блоком:

```text
В незавершённом добавлении учитывай весь диалог: «а во сколько?», «это уже прошло?»
и «а ты не можешь посмотреть?» продолжают исходную просьбу напомнить.
Выбери форму ответа по полноте данных всего списка:
- Если все записи определены и их условия поддерживаются, верни весь список items,
  question=null и question_sources=[]. Для найденного события нужны подтверждённые
  дата, время, IANA-пояс и источник. Не запрашивай повторное согласие на добавление.
  Верни найденный момент и для исторического события: проверку прошлого относительно
  reference_utc выполняет приложение. Сам факт прошедшей даты не требует question.
- Если конкретных данных не хватает, они неоднозначны или условия не поддерживаются,
  верни items=[] и question с вопросом о недостающих данных или изменении условий.
  Не используй question для справочного ответа о найденном времени или сообщения,
  что событие уже состоялось. При известных данных это заменило бы исходную просьбу.
```

## Методика

Временный драйвер использовал существующие `EvaluationRun`, `EvaluationClient`
и два экземпляра `OpenAIParser`. Перед каждым последовательным вызовом подставлялся
соответствующий поисковый блок; остальные настройки и входные данные не менялись.
Никакого дополнительного модельного этапа не добавлено.

В каждом раунде сначала проверялся `web_euro`, затем `web_euro_followup`.
Для каждой пары один и тот же сценарий запускался с обоими вариантами.
Первой парой был порядок контроль/кандидат, второй — кандидат/контроль, затем
они чередовались. Каждый вариант оказался первым в пяти парах.
Точный [порядок всех 20 вызовов](2026-09-27-output-choice-order.json) сохранён.

Кандидат не менялся по ходу набора. Проверки содержания брались из evaluation:
одна запись без уточнения, подтверждённый источник и начало 14.07.2024 19:00 UTC.
Сравнение SHA-256 подтвердило одинаковый набор и одинаковый промпт редактирования,
при различном промпте создания. Все проверки выполнены; пропусков и ошибок API нет.

| Продолжение `web_euro_followup` | 5/5 | 5/5 |
| Всего прошли | **8/10** | **7/10** |
| Завершённые ответы API | 10 | 10 |
| Вызовы веб-инструмента | 10 | 11 |
| Входные токены | 107090 | 108954 |

| Суммарное время API, с | 51,3868 | 48,8105 |

Технические отчёты: [контроль](2026-09-27-output-choice-control.json),
[кандидат](2026-09-27-output-choice-candidate.json). В обоих `finished=true`,
`completed=false`. В шести парах прошли оба варианта, в двух — только контроль,
в одной — только кандидат, ещё в одной не прошёл ни один.

Два отказа контроля присутствовали уже в ответах модели: пустой список и
уточнение с указанием на прошедшее событие. У кандидата два отказа также
пришли как пустой список; в одном из них модель вновь запросила подтверждение.

Третий отказ кандидата имел другую причину. Модель вернула событие, но указала
URL, отсутствующий в результатах текущего поиска: путь страницы начинался с
`/euro2024/`, а не с найденного `/uefaeuro/`. Приложение правильно отклонило
неподтверждённый источник и вернуло уточнение. Поэтому код `expected_items`
в evaluation сам по себе не отличает отказ модели от срабатывания проверки ссылок;
здесь причины установлены по приватной трассировке.

## Решение и ограничения

Улучшение не подтверждено, кандидат отклонён. Рабочий промпт восстановлен
в точности до `3c2e61c`; изменения приложения отсутствуют. Полная платная
проверка 29 сценариев не запускалась, поскольку условие продолжения не выполнено.
В репозитории сохраняются методика, кандидат и все результаты эксперимента.

Пять повторов на сценарий не доказывают устойчивое ухудшение или общую частоту
ошибок. Чередование уменьшает зависимость от порядка, но не фиксирует кеш,
поисковую выдачу и поведение провайдера. Разница времени и числа токенов не
интерпретируется как выигрыш в скорости или стоимости.

До платного сравнения прошли 44 профильных автономных теста. Полный `unittest`:
207 тестов, `OK (skipped=1)`; Unix datagram socket ожидаемо пропущен на Windows.
Ruff, форматирование, ссылки документации и состав технических отчётов проверены
перед фиксацией результатов. Совпадение восстановленного рабочего промпта
с контролем проверено по SHA-256 и отсутствию diff файла parser.
Приватные ответы и SDK-тела в публичные отчёты не переносились.
