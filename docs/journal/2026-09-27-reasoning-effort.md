# Сравнение reasoning low и medium

[Журнал работ](README.md) · [Предыдущий эксперимент](2026-09-27-parse-intent.md)

Дата работы: **27 сентября 2026 года**.

## Гипотеза и условия

После отклонённых изменений промпта проверяется влияние `reasoning.effort`:
даёт ли `medium` меньше лишних уточнений и больше правильных событий, чем `low`,
на той же `gpt-6-luna`. [OpenAI Docs](https://developers.openai.com/api/docs/models/gpt-6-luna)
подтверждает поддержку обоих значений; это не гарантия улучшения данного разбора.

Исходная версия — `4ee6d42`. Промпты, роли контекста, схема ответа, интерфейс
`Parser.parse` и модель одинаковы. Единственный изменяемый параметр API —
`reasoning.effort`. `store=False`, `max_output_tokens=3000`, SDK timeout 30 секунд,
SDK-повторы отключены. Общий бюджет `parse` — 40 секунд, до трёх веб-вызовов
и одна перепроверка. Среда: Windows, Python 3.14.7, OpenAI SDK 2.54.0,
Pydantic 2.13.5, Ruff 0.16.8.

`REASONING_EFFORT` вынесен в одну константу parser, общую для запроса и trace.
Evaluation сохраняет фактически отправленный уровень каждой API-попытки.
Временный сценарий сравнения использует существующие `EvaluationRun` и
`EvaluationClient`, подменяя только константу на время последовательного разбора.
Новых зависимостей, переменных окружения и модельных этапов нет.

## Методика

До первого API-вызова зафиксированы восемь сценариев, пять повторов и два уровня:
ровно **80 платных разборов**, 40 на вариант. Один сценарий сравнивается попарно,
порядок уровней чередуется между парами и повторами.

- Шесть положительных сценариев: `web_euro`, `web_euro_followup`, `web_bst`,
  `web_bst_followup`, `web_czechia_2026`, `web_czechia_2026_followup`.
- Два защитных сценария: `personal_missing_time` и `event_duration`, требующие
  уточнения без поиска личных событий.

Опорные даты и ожидаемые моменты берутся из постоянной evaluation без изменений.
На дату запуска финал Евро и Англия — Испания исторические; Чехия — Англия
предстоит в реальном мире. В каждом сценарии событие должно быть будущим
относительно переданного контекста приложения. Поиск живой, выдача не фиксируется.

Условия перехода к полному платному набору из 33 сценариев зафиксированы заранее:

- У `medium` больше успешных положительных сценариев и меньше разборов с пустым
  списком и вопросом до валидации приложения.
- Все десять защитных разборов `medium` проходят без веб-вызовов.
- Разборов с неподтверждёнными URL не больше, чем у `low`.
- Оба варианта завершают все API-попытки; техническая и приватная диагностика
  полная, исходные бюджеты соблюдены.
- P95 всего `parse` у `medium` не больше 30 секунд и не больше удвоенного P95
  контроля. Это условие данного эксперимента, не новый runtime-таймаут.
- Для принятия `medium` дополнительно требуется прохождение всех 33 сценариев
  полного набора одним прогоном. Повторы ради получения другого результата
  не предусмотрены.

Сопоставляются одинаковые хеши набора, промптов и первых входов. Хеши параметров
должны совпасть после нормализации только `reasoning.effort`.
Счётчики пустых ответов и неподтверждённых URL собираются до валидации parser;
они не устанавливают внутреннюю причину решения модели. Тексты и ссылки остаются
в приватных JSONL. В репозиторий переносятся только технические метрики.

| `web_bst_followup` | 4/5 | 4/5 |
| `web_czechia_2026` | 4/5 | 5/5 |

| Положительные сценарии вместе | **27/30** | **28/30** |
| Пустой список с вопросом в положительных сценариях | **3** | **2** |
| `personal_missing_time` | 5/5 | 5/5 |
| `event_duration` | 5/5 | 5/5 |
| Веб-вызовы в защитных сценариях | 0 | 0 |
| Разборы с неподтверждёнными URL | 0 | 1 |
| Все проверки | **37/40** | **38/40** |

У `low` не прошли `web_czechia_2026` в повторе 2, `web_euro` в повторе 3
и `web_bst_followup` в повторе 5. Во всех трёх ответах модели уже были
пустой список и вопрос; неподтверждённых ссылок нет.

У `medium` не прошли `web_euro_followup` и `web_bst_followup` в повторе 2.
Оба вернули пустой список с вопросом. В первом дополнительно обнаружен URL
в `question_sources`, отсутствующий среди результатов инструмента; приложение
его отклонило. Счётчики лишних вопросов и неподтверждённых URL пересекаются,
это не три разных отказа. Во втором вопрос появился после внутренней перепроверки.

В 35 парах прошли оба уровня, в трёх — только `medium`, в двух — только `low`.
У `medium` две внутренние перепроверки: `web_bst`, повтор 1, завершился успешно;
`web_bst_followup`, повтор 2, завершился вопросом. У `low` перепроверок не было.
Все **82 API-попытки** завершились; ошибок API, пропусков и отмен нет.
У обоих вариантов `finished=true`, `completed=false`. Входы и параметры после
нормализации только effort совпали; диагностика всех попыток полная.

бюджет 40 секунд и три вызова инструмента соблюдён. У `medium` P95 вырос
в 2,63 раза, reasoning-токенов использовано в 2,49 раза больше. Стоимость
в валюте не рассчитывалась; поиск и кеширование также различаются.

## Решение и ограничения

`medium` **не принят**. На один положительный результат больше и на один лишний
вопрос меньше, но нарушены два заранее заданных условия: появился неподтверждённый
URL и P95 превысил удвоенное время контроля (12,9892 секунды). Полный платный
набор из 33 сценариев не запускался; дополнительные повторы не выполнялись.
Рабочая настройка остаётся `low`, промпты не менялись.

Малое число повторов не доказывает устойчивое преимущество или ухудшение качества.
Поисковая выдача, кеширование и нагрузка локальной машины не фиксировались;
часть сравнения выполнялась одновременно с автономными тестами. Задержки
описывают этот запуск и не являются SLA. Две из трёх пар матчей исторические
в реальном мире, хотя будущие относительно контекста сценария. Результат
не переносится автоматически на другие уровни reasoning или модели.

В коде сохранены единая константа effort и её запись в метриках evaluation.
Расширены существующие автономные проверки: trace и SDK получают одинаковый
уровень при обеих попытках; технический отчёт сохраняет только поле effort,
без приватных полей reasoning, а отсутствие параметра отражает как `null`.
Сходство всего AST parser с исходной версией проверено после подстановки
константы: иных изменений логики нет.

Полный `unittest` на Python 3.14.7: **209 тестов**, `OK (skipped=1)`;
Unix datagram socket ожидаемо пропущен на Windows. Все 46 профильных тестов,
Ruff, форматирование, `git diff --check`, локальные ссылки и якоря документации
прошли. Проверки на Linux не выполнялись.

Production, Telegram, пользовательская БД, `.env`, зависимости и интерфейс
`Parser.parse` не менялись. Ключ использовался только внутри процесса оплаченного
синтетического сравнения согласно разрешению пользователя.
