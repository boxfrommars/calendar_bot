# Два примера выбора готовых записей и уточнения

[Журнал работ](README.md) · [Предыдущее сравнение](2026-09-27-current-full.md)

Дата работы: **27 сентября 2026 года**. Исходная версия — `e44db16`.

## Гипотеза и кандидат

Два коротких примера входа и правильного выхода могут уменьшить число уточнений
вместо готового события, сохранив обязательные вопросы при нехватке данных.
Проверяется только добавление [этого блока](2026-09-27-output-examples-prompt.txt)
в конец `CREATE_INSTRUCTIONS`. Схема, роли, остальной промпт, модель `gpt-6-luna`
и reasoning `low` остаются прежними. Редактирование не получает этот блок.

Примеры синтетические и отсутствуют среди проверочных сценариев: подтверждённая
лекция и смешанный список с неопределённым спектаклем. Учебный источник нельзя
использовать в реальном ответе; проверка происхождения URL не меняется.
Оба JSON-ответа проверяются существующим `ParseResult` до платного запуска.
Подход согласуется с [рекомендацией OpenAI о примерах](https://developers.openai.com/api/docs/guides/reasoning-best-practices#how-to-prompt-reasoning-models-effectively):
примеры должны соответствовать инструкциям. Это не подтверждение выигрыша
для конкретной модели — его проверяет эксперимент.

## Условия, зафиксированные до запуска

Используется существующая инфраструктура `EvaluationRun` и `EvaluationClient`.
Порядок вариантов в каждой паре меняется между сценариями и повторами.
Входы первых попыток должны совпасть после удаления только блока примеров;
параметры SDK и фактическая JSON-схема должны совпасть полностью. Блок остаётся
неизменным до завершения всех запланированных проверок.

Первый этап: десять сценариев, четыре повтора, два варианта — **80 разборов**.
Шесть положительных веб-сценариев: `web_euro`, `web_euro_followup`, `web_bst`,
`web_bst_followup`, `web_czechia_2026`, `web_czechia_2026_followup`.
Четыре защитных: `personal_missing_time`, `event_duration`, `web_ambiguous`,
`web_fictional`. Проверяются поля и наличие вопроса, без сравнения текста.

Условия перехода к полному сравнению:

- Не менее двух дополнительных успешных положительных разборов из 24 и
  минимум на два меньше пустых ответов с вопросом на этих сценариях.
- Выигрыш по положительным сценариям минимум в двух из четырёх повторов;
  проигрыш не более чем в одном повторе.
- Все 16 защитных разборов кандидата проходят; личные события не вызывают поиск.
- У кандидата нет неподтверждённых URL. У обоих вариантов полная диагностика,
  все ответы API завершены, сохранены полные приватные запросы и ответы.
- У каждого разбора соблюдены 40 секунд, максимум три вызова поиска и одна
  перепроверка. P95 кандидата не выше 15 секунд и 1,5 P95 контроля.

Только при выполнении этих условий запускается полное попарное сравнение:
33 сценария по три раза для каждого варианта — ещё **198 разборов**.
Для принятия нужны не менее трёх дополнительных успешных разборов из 99,
меньше пустых ответов с вопросом на положительных веб-сценариях и выигрыш
на них минимум в двух из трёх повторов без проигранных повторов. Все сценарии
без поиска и оба защитных веб-сценария кандидата должны проходить каждый раз;
остальные требования к источникам, диагностике, лимитам и P95 сохраняются.
Совершенный результат 99/99 сам по себе не требуется. Это инженерные пороги
для ограниченного эксперимента, не проверка статистической значимости.

Неудачные разборы не перезапускаются выборочно. При невыполнении любого условия
дальнейшие платные этапы не запускаются, рабочий промпт сохраняется.
Суммарный предел эксперимента — 278 разборов, включая оба варианта и оба этапа.
