# Обновление всех зависимостей в пределах текущих ограничений

## Задача

Обновить прямые и транзитивные production-зависимости до последних совместимых
релизов, сохранив ограничения `requirements.in`, Python 3.14 и минимум безопасности
certifi после компрометации цепочки emSign.

## Контекст и условия

- Дата работы: 2026-10-27; исходная версия репозитория: `2e62fb7`.
- Проверка установки и тестов: Windows, Python 3.14.8, отдельное чистое виртуальное
  окружение. Служебные инструменты: uv 0.13.4, pip 26.2.2, Ruff 0.16.8.
- pip в проверочном окружении обновлён локальным официальным wheel с проверкой
  SHA-256 до первого сетевого обращения установщика.
- Верхние границы прямых зависимостей сохранены. OpenAI SDK остаётся на 2.54.0
  при ограничении `<3`. Pydantic остаётся на 2.13.5, поскольку
  [aiogram 3.31.0](https://pypi.org/pypi/aiogram/3.31.0/json) требует `pydantic<2.14`.

## Изменения

Lock пересоздан через uv с обновлением всех разрешённых версий:

```sh
uv pip compile requirements.in --universal --python-version 3.14 --generate-hashes --upgrade --output-file requirements.txt --cache-dir .cache/uv
```

В lock осталось 31 имя пакета; обновились пять:

| Пакет | До | После |
| --- | --- | --- |
| [aiohttp](https://pypi.org/project/aiohttp/3.14.5/) | 3.14.3 | 3.14.5 |
| [jiter](https://pypi.org/project/jiter/0.18.0/) | 0.17.0 | 0.18.0 |
| [multidict](https://pypi.org/project/multidict/7.2.1/) | 6.9.1 | 7.2.1 |
| [python-dotenv](https://pypi.org/project/python-dotenv/1.2.4/) | 1.2.3 | 1.2.4 |
| [tzdata](https://pypi.org/project/tzdata/2026.5/) | 2026.4 | 2026.5 |

В lock изменились только блоки этих пяти пакетов вместе с автоматически
рассчитанными хешами. Исходные ограничения не менялись.
certifi остался на 2026.10.23.

Multidict обновился до 7.x в пределах ограничений новой версии aiohttp.
[Changelog multidict](https://multidict.aio-libs.org/en/stable/changes/)
описывает несовместимость наследования от `istr`; приложение напрямую этот API
не использует. Совместимость HTTP-слоя дополнительно проверена локальным API.

В руководстве разработки описано полное обновление через `--upgrade`; контракт
размещения уточняет проверку установки lock в чистое окружение. Код приложения
и схема БД не менялись.

## Проверка и результаты

Чистая установка всех production-зависимостей через
`python -m pip install --require-hashes -r requirements.txt` прошла на Python 3.14.8.
`python -m pip check` не обнаружил несовместимых требований.
Версии всех пакетов (31) совпали с lock. Метаданные пяти обновлённых релизов
и все их хеши в lock отдельно сверены с официальным PyPI; отозванных релизов нет.

Локальный HTTP smoke-тест использовал настоящий `AiohttpSession` aiogram и
подставной HTTP-сервер на `127.0.0.1` со случайным портом. Успешны `getMe`, пустой
`getUpdates` и `sendMessage` с кириллицей и emoji; запросы формы и JSON-ответы
прошли через новые aiohttp и multidict. Внешний Telegram API не вызывался.

Корень `emSign ECC Root CA - G3` по-прежнему отсутствует среди CA, загруженных
из certifi в отдельный `ssl.SSLContext`.

Команды автономной проверки:

```sh
python -m unittest discover -s tests -q
ruff check calendar_bot tests
ruff format --check calendar_bot tests
```

Полный набор в чистом окружении: 218 тестов, успешно; один интеграционный тест
Unix datagram socket пропущен на Windows по условию платформы. Набор и локальный
HTTP smoke выполнены вне sandbox из-за ограничений на локальные сокеты
Windows asyncio. Тесты использовали синтетические данные и подставные API.

Ruff lint и проверка формата прошли: 37 Python-файлов соответствуют формату.
Локальные ссылки документации и `git diff --check` проверены.

После проверки основное локальное окружение обновлено тем же lock;
`python -m pip check` успешен, версии всех пакетов (31) соответствуют lock.

## Ограничения

Рабочий бот, пользовательские БД и backup не использовались. Платная OpenAI
evaluation, production-развёртывание и проверка на Linux не выполнялись.
