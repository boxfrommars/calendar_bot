# Роль служебного времени и предстоящие веб-события

[Журнал работ](README.md) · [Предыдущий эксперимент](2026-09-27-output-choice.md)

Дата работы: **27 сентября 2026 года**.

## Задача и условия

Проверить, помогает ли роль `developer` для опорной даты и времени при добавлении
события. В предыдущих измерениях модель иногда считала событие прошедшим вопреки
`reference_utc` или запрашивала дополнительное подтверждение найденного времени.
По [документации OpenAI](https://developers.openai.com/api/docs/guides/prompt-engineering)
сообщения `developer` имеют приоритет над `user`; это основание для гипотезы,
а не гарантия правильной календарной интерпретации.

Контроль — `OpenAIParser` из `04f98f1`, передающий контекст приложения как `user`.
Кандидат меняет только роль этого сообщения на `developer`, когда `base is None`.
Тексты всех четырёх блоков инструкций, входной диалог, даты, схема ответа,
`Parser.parse` и параметры API сохранены. При редактировании контекст остаётся
`user`, поскольку `selected_item` содержит пользовательское название. Названия,
диалог и диагностика прошлой попытки не получают служебного приоритета.

Среда: Windows, Python 3.14.7, OpenAI SDK 2.54.0, Pydantic 2.13.5, Ruff 0.16.8.
Модель всех ответов — `gpt-6-luna`, `reasoning.effort=low`,
`max_output_tokens=3000`, `store=False`; SDK-повторы отключены. Каждый `parse`
сохраняет предел 40 секунд, три вызова инструмента и одну перепроверку.
Использовались синтетические примеры и разрешённая платная evaluation.
Production, Telegram и пользовательские данные не затрагивались.

## Методика

Первое сравнение включало `web_euro` и `web_euro_followup`: два варианта,
по пять повторов каждого сценария, всего 20 разборов. Порядок внутри пар
чередовался, кандидат не менялся. Предварительное условие перехода к полному
набору — больше пройденных проверок, чем у контроля.

Временный драйвер использовал существующие `EvaluationRun`, `EvaluationClient`
и два класса parser. Контрольный класс извлечён из указанной ревизии через AST
и исполнялся с теми же типами и функциями валидации. Равенство текстов инструкций
проверено до запуска. Для каждой пары проверено совпадение параметров и схемы,
а также входов после нормализации только роли сообщения контекста.
Значения ролей и хеши фактических входов сохранены в технических манифестах.
`prompt_sha256` у вариантов одинаков: он учитывает тексты инструкций, но не роли.

После первого сравнения полный набор расширен двумя примерами матча
Чехия — Англия 29.09.2026: прямым запросом и продолжением диалога. Опорная дата
фиксирована — 27.09.2026 08:00 UTC, ожидаемое начало — 29.09.2026 18:45 UTC.
[England Football](https://www.englandfootball.com/articles/2026/Aug/06/Czechia-Away-Registration-Open)
указывает 20:45 местного времени в Праге и 19:45 BST. В отличие от двух прежних
матчей этот был предстоящим и в реальном мире на дату измерения. Он не будет
автоматически заменяться или сдвигаться по мере устаревания.

Полный прогон кандидата из 31 сценария выявил два отказа. Поскольку новые
примеры прежде не измерялись на контроле, для них выполнено отдельное второе
сравнение: те же два варианта, пять повторов каждого из двух сценариев, ещё
20 чередующихся разборов. До его начала зафиксировано условие принятия:
кандидат не должен ухудшить новые сценарии и должен сохранить общий перевес
в двух попарных сравнениях. Неудачный полный прогон не исключался из отчёта.

## Решение и проверки

Кандидат принят по заранее указанному условию. Служебный контекст добавления
передаётся как `developer`; редактирование сохраняет прежнюю роль. Текст промптов
не менялся. Сравнения показывают предварительный выигрыш на четырёх выбранных
сценариях, но не доказывают общую частоту ошибок или статистически устойчивое
улучшение. Ложные уточнения остаются, включая запрос о предстоящем событии.
Проблема неточного копирования URL также остаётся предметом отдельного
эксперимента; проверка происхождения ссылок не ослаблена.

Автономная регрессия проверяет, что пользовательское сообщение и название
выбранной записи не попадают в `system`/`developer`, а переданное время сохраняется,
в том числе на границе местного дня. Полный `unittest` на Python 3.14.7:
208 тестов, `OK (skipped=1)`; Unix datagram socket ожидаемо пропущен на Windows.
После добавления новых веб-сценариев отдельно прошли все 15 тестов evaluation
и контракта parser. Ruff, форматирование, `git diff --check`, локальные ссылки
и якоря документации проверены. Проверки на Linux в этот этап не выполнялись.

Новые зависимости, миграции, дополнительные модельные этапы и отдельный runner
не понадобились. Правила ролей, фиксированных сценариев и сравнения хешей
добавлены в [руководство разработчика](../development.md#платная-evaluation).
