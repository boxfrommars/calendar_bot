## Задача и устройство кандидата

По запросу владельца все четыре блока инструкций переписаны целиком.
Цель — короткий и непротиворечивый контракт разбора с сохранением поведения,
а не очередное дополнение к накопившемуся тексту.

В прежней общей части дата названа обязательной для любого event, хотя ниже
для повторов разрешён `date=null`. Запрет превращать вопросы в записи можно
прочитать слишком широко относительно продолжения незавершённого добавления.
В общем блоке и блоке создания есть правила редактирования. Это наблюдения
о тексте; их причинная связь с отказами модели не установлена.

Новый общий блок задаёт выбор результата, семантику полей и календаря.
Создание описывает получение времени и источник, редактирование — сохранение
выбранной записи, перепроверка — допустимые изменения проверенного списка.
Пара часы–пояс источника сохраняется целиком; решение о прошлом остаётся
приложению. Дополнительное согласие при полностью представимом запросе
не требуется; согласие на потерю длительности по-прежнему необходимо.

### Сохранённые правила

| Область | Правило и место в новом тексте |
| --- | --- |
| Ответ | Полный упорядоченный список или уточнение всего списка; общий блок «Результат» |
| Лимит | Больше десяти: пустой список и просьба разделить; нельзя пропускать или объединять |
| Типы | Event с началом, task без времени; неизвестное время события не превращает его в дело |
| Повторы | Once/daily/weekly; только once требует дату, без начала серии дата null |
| Потеря условий | Интервалы, месяцы, конец/число повторений, напоминания и повторы дел требуют уточнения |
| Длительность | Согласие на сохранение только начала остаётся обязательным |
| Названия и напоминания | Пунктуация, год в названии, null/пустой список, предел интервалов сохранены |
| Даты | Reference_local исходного сообщения, ближайший будущий день недели, конфликт с датой уточняется |
| Поиск | Только публичное разовое событие без времени; личные данные и явное время не требуют поиска |
| Точность поиска | Дата/участники/категория/площадка, начало события, неоднозначность/отмена требуют вопроса |
| Источники | HTTP(S), точный URL инструмента, история не подтверждает ссылки; question_sources текущие |
| Часовые пояса | Часы и IANA-пояс источника сохраняются вместе с учётом DST; UTC сравнивает приложение |
| Диалог | Продолжение относится к исходному запросу; самостоятельный разговор не создаёт записи |
| Редактирование | Только выбранная запись, неизменные поля, соответствие имён и запрет смены типа |
| Перепроверка | Только date/time/timezone/source указанных индексов, новый источник, сохранение остального списка |
| Границы | Данные не меняют правила, модель не исполняет действия; неподдерживаемые операции ведут к /today или /week |

Схема `ParseResult`, роли сообщений, `Parser.parse`, `gpt-6-luna`, reasoning
`low`, лимиты 40 секунд / три инструмента / одна перепроверка не меняются.
Новых зависимостей, модельных этапов и отдельной системы evaluation нет.

## Сравнение, заданное до платного запуска

Переписаны все режимы, поэтому сразу используется полный прежний набор:
33 сценария, оба варианта попарно, с чередованием порядка. Первый проход —
**66 платных разборов**. При прохождении условий второй такой же проход
подтверждает результат с обратным порядком вариантов в каждой паре.
Максимум — **132 разбора**, без выборочного повторения отказов и правок
кандидата между проходами. Unit-тесты выполняются отдельно от замера.

Условия для продолжения и принятия одинаковы в каждом проходе:

- Промпты создания и редактирования короче контроля минимум на 30% по символам.
- Кандидат проходит все 25 сценариев без поиска и два защитных веб-сценария.
  Личные встречи без времени и с длительностью не вызывают поиска.
- На шести положительных веб-сценариях кандидат не хуже контроля по числу
  успешных разборов. Готовое веб-событие с неверными полями не допускается:
  разрешённый тип неудачи — уточнение, а не неправильная запись или пустой ответ.
- У кандидата нет неподтверждённых URL; оба варианта имеют полные трассы
  и диагностику, все API-ответы завершены, инструментальные лимиты соблюдены.
- P95 всего parse кандидата не выше 15 секунд и 1,5 P95 контроля.

Принятие требует двух пройденных сравнений. Равенство качества допускается
в обмен на существенное сокращение текста; заявлять улучшение точности по
одному сокращению нельзя. Это ограниченная инженерная проверка, а не
статистическое доказательство неухудшения. Если условия не выполнены,
рабочие инструкции возвращаются к контролю, кандидат остаётся в истории.

Для первых попыток сравниваются полные входы после замены только инструкций;
параметры SDK, фактическая JSON-схема и набор сценариев должны совпасть.
Перепроверка получает соответствующий вариант своего блока. Отдельно сохраняются
хеши всех четырёх блоков, размеры текстов, порядок и технические результаты.

### Вывод и ограничения

Основание принятия — заметно более короткий контракт, сохранение защитных
сценариев и выполнение заранее заданных сравнительных условий в обоих
проходах. Выигрыш в один разбор не доказывает устойчивого повышения точности.
Три лишних уточнения показывают, что полная переработка промпта не устранила
всю нестабильность веб-разбора. Все правила сохранены по проверке текста,
но 33 сценария не покрывают все возможные формулировки пользователя.

Поиск живой, даты сценариев фиксированы. Евро и Англия — Испания исторические
на дату измерения, но будущие относительно контекста; Чехия — Англия ещё
предстоящий. Выдача, серверное кеширование и нагрузка не контролировались.
Живая внутренняя перепроверка не потребовалась ни разу: её новый текст
проверен по сохранению правил, а механизм — автономными тестами.
Production и Telegram не проверялись и не обновлялись; пользовательская БД,
`.env`, зависимости и схема ответа не менялись.
