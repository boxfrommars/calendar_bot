## Задача и условия

По явному запросу пользователя выполнена живая evaluation после исправления
перепроверки источников и правил полноты списка. Проверялась та же рабочая копия
поверх `b24851d`, что описана в [предыдущей записи](2026-09-27-parser-recheck.md).
После автономных проверок код и промпты перед платным запуском не менялись.

Окружение: Windows, Python 3.14.7, OpenAI SDK 2.54.0, Pydantic 2.13.5.
Запуск использовал действующую конфигурацию evaluation и настроенный доступ
к OpenAI API. Параметры parser: `reasoning.effort=low`,
`max_output_tokens=3000`, `store=False`. По последующему уточнению владельца
в локальной конфигурации, использованной для запуска, выбрана `gpt-6-luna`.
Сам runner на момент этого прогона эффективное имя модели не выводил;
атрибуция модели основана на уточнении владельца, а не на сохранённых метаданных API.

Использовались только примеры из [evaluation](../../calendar_bot/evaluation.py).
Рабочий бот не запускался; записи календаря и Telegram-сообщения не создавались.
Секреты и приватные диагностические JSONL в отчёт не включались.

## Способ проверки

Из виртуального окружения Python 3.14 выполнен один полный проход:

```sh
python -B -u -m calendar_bot.evaluation --web-search
```

Опция `--web-search` включает как базовые проверки, так и дополнительные
поисковые сценарии. Даты отсчёта фиксированы в примерах: 24 сентября 2026 года
для основного набора, 14 июля 2024 года для финала Евро и 26 сентября 2026 года
для проверки BST. Проверяются структурированные поля и результат нормализации,
либо пустой список с непустым вопросом; текст вопроса не сравнивается буквально.

## Ограничения

Это один проход каждого сценария, без сравнения со старым промптом и без оценки
статистической устойчивости. Фактическое число внутренних попыток и поисковых
вызовов, расход токенов, стоимость и задержка runner не отчитал; они не измерялись
отдельно. Улучшение скорости или стоимости не утверждается.

Проверка неизменённого соседнего источника при внутренней перепроверке остаётся
автономной регрессией с подставным API. Живой набор не принуждает модель к такому
промежуточному ошибочному ответу и не доказывает, что этот путь был выполнен.
Методика запуска и границы проверки описаны в
[руководстве разработчика](../development.md#платная-evaluation).
