# Полное расписание и отдельный выбор записи

## Задача

Заголовок «7 дней» показывал весь выбранный диапазон, но первая страница
содержала только восемь записей. При открытии периода со среды по вторник
понедельник и вторник могли оказаться за незаметной кнопкой «Страница →».
Переход «7 дней →» открывал следующий период снова с первой страницы,
поэтому возникало впечатление, что повторяющиеся события пропали.

## Контекст и условия

- Дата работы: 2026-10-21; исходная версия: `5374498`.
- Локальная проверка: Windows, Python 3.14.8, Ruff 0.16.8, существующее
  виртуальное окружение проекта. Зависимости и схема SQLite не менялись.
- Использовались только синтетические события и дела, временные SQLite-БД,
  управляемые часы и подставной Telegram API. Рабочий бот, личная БД и платная
  OpenAI evaluation не использовались.
- Sandbox блокировал локальную пару сокетов Windows asyncio. Асинхронные
  проверки выполнялись вне sandbox; внешняя сеть для них не требовалась.

## Изменения

- Полные «Сегодня» и «7 дней» получают все записи периода в общей транзакции;
  переданный clock фиксирует время выборки и оформления.
- Длинный обзор автоматически продолжается сообщениями до 3500 единиц UTF-16.
  Запись вместе с пояснением не разрывается. Повторяются диапазон и заголовок
  дня, сохраняются общая нумерация, количество записей и время снимка.
- «Выбрать запись» открывает отдельное меню, где осталось разбиение до восьми
  доступных записей. Можно выполнить дело, вернуть его в работу или открыть
  карточку. Уже начавшиеся встречи доступны только в обзоре.
- Каждый обзор отправляется новыми сообщениями. Меню и карточки обновляются
  только в нажатом сообщении; возврат к обзору создаёт новый актуальный снимок.
  Идентификаторы групп сообщений не сохраняются.
- Старые callback сохраняют выбранные даты. Прежний номер страницы обзора
  больше не ограничивает число показанных записей. Новый контекст `j` сохраняет
  страницу выбора через карточки, подтверждения и диалог изменения.

## Проверка и результаты

Регрессия воспроизводит период 21–27 октября на двух синтетических сериях
по будням и двух разовых событиях: все 12 записей, включая понедельник и
вторник, видны без перехода на другую страницу. Отдельно проверены длинные
названия с emoji, целостность записей, UTF-16 entities, автоматические части,
отсутствие изменений старых снимков и очереди при просмотре.

Команды проверки из активного окружения Python 3.14:

```sh
python -m unittest discover -s tests -q
ruff check calendar_bot tests
ruff format --check calendar_bot tests
```

Полный набор: 218 тестов, успешно, один интеграционный тест Unix datagram socket
пропущен в Windows по условию платформы. После финальных изменений оформления
отдельно прошли 30 тестов domain/presentation и три сценария Telegram: неделя
со среды по вторник, длинный снимок с действиями и справка. Ruff lint и проверка
формата прошли; локальные ссылки документации проверены.

## Ограничения

Старые обзоры сохраняют состояние дел на момент снимка. Для актуального полного
списка требуется новый просмотр или «К расписанию»; старые кнопки выбора читают
текущее состояние выбранного периода. Отправка нескольких частей не атомарна
на стороне Telegram: при ошибке доставки можно повторно запросить весь список.
Измерение производительности и живой smoke-тест Telegram не проводились.
