# Проверка инструкции о точном копировании URL

[Журнал работ](README.md) · [Предыдущий эксперимент](2026-09-27-context-role.md)

Дата работы: **27 сентября 2026 года**.

## Задача и условия

В предыдущих измерениях модель иногда возвращала время с URL, которого не было
в метаданных поиска. Например, она меняла раздел сайта в пути страницы. Приложение
правильно отклоняло весь список, но общий код `expected_items` скрывал различие
между таким отказом и пустым ответом самой модели.

Проверяемая гипотеза: требование копировать полный URL посимвольно уменьшит
число неподтверждённых источников. Проверка ссылок в приложении остаётся строгой;
никакой подстановки похожей страницы или автоматического исправления URL нет.
[OpenAI Docs](https://developers.openai.com/api/docs/guides/tools-web-search#sources)
описывает `sources` как список найденных инструментом URL; это источник данных
для проверки, но не гарантия точного копирования моделью.

Контроль — промпт из `0daf5d4`. Кандидат добавляет сразу после определения
`source={title,url}` три строки в `CREATE_INSTRUCTIONS`:

```text
В source.url и question_sources[].url копируй полный URL результата web_search
посимвольно: схему, домен, путь, параметры и фрагмент. Не сокращай и не исправляй
ссылку, не восстанавливай её по названию страницы или памяти.
```

Остальной AST файла parser совпадает с контролем, что проверено до запуска.
Схема ответа, `Parser.parse`, контекст времени в роли `developer`, редактирование,
правила перепроверки и параметры API сохранены. Модель — `gpt-6-luna`,
`reasoning.effort=low`, `max_output_tokens=3000`, `store=False`; SDK-повторы
отключены. На один `parse` по-прежнему отводятся 40 секунд, три вызова инструмента
и одна перепроверка.

Среда: Windows, Python 3.14.7, OpenAI SDK 2.54.0, Pydantic 2.13.5, Ruff 0.16.8.
Данные синтетические; production, Telegram и пользовательские записи не затронуты.
Ключ загружался внутри разрешённого диагностического процесса без вывода `.env`.
Ответы и результаты поиска записывались только в приватные JSONL.

## Методика

Заранее зафиксированы четыре сценария: `web_euro`, `web_euro_followup`,
`web_czechia_2026`, `web_czechia_2026_followup`. Для каждого варианта выполнено
по пять повторов, всего 40 последовательных платных разборов. Внутри каждой
пары использован одинаковый сценарий; порядок вариантов чередовался. Кандидат
не менялся по ходу набора. Опорные даты и ожидаемые моменты брались из
существующей evaluation, без подстройки под ответы.

Условие принятия, сохранённое до первого API-вызова: у кандидата должно быть
строго меньше разборов с неподтверждёнными URL, при этом общее число успешных
разборов не должно снижаться. Нужна полная диагностика всех попыток. Отсутствие
ошибки ссылок у контроля означает, что её уменьшение не подтверждено. Полный
платный набор запускается только после выполнения этого условия.

Временный драйвер использует существующие `EvaluationRun` и `EvaluationClient`.
Для каждой первой попытки записаны хеши входов, параметров и схемы; после
нормализации только текста `CREATE_INSTRUCTIONS` входы и параметры должны
совпадать. `suite_sha256` и хеш редактирования должны совпадать, хеш промпта
создания — отличаться. Отдельный фреймворк и дополнительные модельные этапы
не добавлены.

Перед валидацией parser драйвер считал число записей, наличие вопроса, количество
URL событий и вопросов, а также сколько из этих URL отсутствует среди фактических
результатов инструмента. Диагностика содержит только счётчики, статус и ID
сценария/повтора/попытки. Разбор с любым неподтверждённым URL учитывается один раз.
Каждый из выбранных сценариев ожидает одно веб-событие; исключение перепроверки
для сохранённого источника другого, неизменённого события здесь неприменимо.

В 17 парах прошли оба варианта, в двух — только контроль, в одной — только
кандидат. Контроль не прошёл `web_euro` в пятом повторе. Кандидат не прошёл
`web_euro_followup` во втором и `web_czechia_2026` в пятом повторе.
У всех трёх ответов уже до валидации были `items=[]` и непустой вопрос;
все приложенные к ним URL присутствовали в результатах инструмента.
Проверка происхождения ссылок не была причиной этих отказов.

Все 40 попыток завершились, внутренней перепроверки не было. Ошибок API,
пропусков и отмен нет. У обоих вариантов `finished=true`, `completed=false`.
Совпадение входов после нормализации исследуемого блока и неизменность параметров
подтверждены хешами. Разницу времени и токенов не считаем доказанным выигрышем:
поисковая выдача, кеширование и поведение провайдера не фиксировались.

## Решение и ограничения

Кандидат **отклонён**: уменьшение ошибок ссылок не продемонстрировано, общее число
успехов ниже контроля. Рабочий parser восстановлен в точности до `0daf5d4`;
текст кандидата сохранён выше только для воспроизводимости эксперимента.
Полный платный набор из 31 сценария не запускался, поскольку условие перехода
к нему не выполнено. Дополнительные повторы ради получения другого результата
не выполнялись.

Пять повторов на сценарий не доказывают устойчивое ухудшение кандидата. Ошибка
копирования URL в этом эксперименте не воспроизвелась даже у контроля; её
отсутствие не отменяет ранее наблюдавшиеся случаи и не означает исправления.
Повторно проявились лишние уточнения, в том числе для предстоящего события.
Они требуют отдельной гипотезы о выборе между записью и вопросом, а не ослабления
проверки источников или автоматической подстановки ссылок.

В репозитории остаётся автономная регрессия точного сравнения URL: 54 подслучая
для `search`, `open_page` и `find_in_page`, событий и уточнений. Полная ссылка
принимается; изменения схемы, домена, пути, кодирования, завершающего слеша,
параметров, их порядка или фрагмента отклоняются. Ошибка источника события
отклоняет и соседнее дело, сохраняя атомарность списка.

Полный `unittest` на Python 3.14.7: 209 тестов, `OK (skipped=1)`; Unix datagram
socket ожидаемо пропущен на Windows. До платного сравнения и после восстановления
промпта прошли все 46 профильных тестов parser, evaluation и приватной диагностики.
Ruff, форматирование, `git diff --check`, локальные ссылки и якоря документации
проверены. На Linux проверки не выполнялись.

[Руководство разработчика](../development.md#платная-evaluation) дополнено правилами
точного сравнения URL и разделения причин отказа при измерениях. Рабочая модель,
схема ответа, интерфейс parser, зависимости и лимиты поиска не изменились.
