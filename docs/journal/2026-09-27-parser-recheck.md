# Перепроверка источников и полнота разбора

[Журнал работ](README.md) · [Разработка и диагностика](../development.md)

Дата изменений и автономных проверок: **27 сентября 2026 года**.

## Задача

Аудит промптов 26 сентября выявил ложный отказ при перепроверке времени одного
из нескольких публичных событий. Промпт требовал сохранить остальные записи,
но вторая попытка принимала только заново найденные ссылки и отклоняла источник
неизменённого соседнего события. Отдельные пробелы инструкций допускали усечение
списка длиннее десяти записей и потерю неподдерживаемых условий повторения.

## Контекст и версии

- Исходная версия: `b24851d`; проверялись изменения рабочей копии поверх неё.
- Windows, Python 3.14.7, OpenAI SDK 2.54.0, Pydantic 2.13.5, Ruff 0.16.8.
- Использовались синтетические записи, управляемое время и подставной OpenAI API.
  Пользовательские БД, секреты, диагностические JSONL и внешние API не использовались.
- Параметры parser: `reasoning.effort=low`, `max_output_tokens=3000`, `store=False`.
  Живая модель в этом исследовании не запускалась. По последующему уточнению
  владельца рабочая модель локально и в production — `gpt-6-luna`;
  автономные проверки использовали подставной API.

## Изменения

В [парсере](../../calendar_bot/parser.py) проверенный первый результат хранится
только до завершения текущего разбора. Источник разрешено сохранить для полностью
неизменённой записи на прежней позиции, если она не требует перепроверки.
У перепроверяемых событий можно исправлять только дату, время, пояс и источник;
каждый источник должен быть найден в текущей попытке, даже если время осталось
прежним. Состав и порядок списка защищены проверкой полей. Старые ссылки не
становятся общим разрешённым набором для других записей или `question_sources`.

В промпте явно запрещено сокращать, объединять или пропускать записи ради лимита.
Запрос свыше десяти записей требует уточнения без частичного списка. Условия,
которые нельзя представить без потерь, также требуют уточнения: интервалы в
несколько дней/недель, конец серии и число повторений. Ежедневные повторы и дни
каждой недели остаются поддерживаемыми.

В [evaluation](../../calendar_bot/evaluation.py) добавлены девять синтетических
сценариев: два допустимых повтора, списки из десяти и одиннадцати записей, интервалы
в несколько дней и недель, дата окончания, число повторений и смешанный список
с неподдерживаемым условием. Отдельный фреймворк оценки не вводился.

## Проверки и результаты

В [тесты парсера](../../tests/test_parser.py) добавлены семь регрессионных тестов
с дополнительными подслучаями. Подтверждены сохранение соседнего веб-события
и дела при перепроверке, требование свежего источника для каждого перепроверяемого
события, запрет подмены записей и переноса доверия к ссылке в следующий разбор.
Проверены также пустой/сокращённый список, добавление и перестановка записей,
изменение напоминаний, типа, повторения и полей соседних записей.

Профильный набор parser/domain/model_trace: 45 тестов успешно. После добавления
проверки полностью опустевшего списка повторно выполнены 26 тестов парсера — успешно.
Полный автономный набор: 195 тестов, результат `OK (skipped=1)`; на Windows
ожидаемо пропущена интеграция Linux Unix datagram socket. `ruff check` и
`ruff format --check` прошли для всех 36 Python-файлов. Проверены 47 локальных
ссылок и якорей в затронутой документации, ошибок нет; `git diff --check` прошёл.
Статическое сравнение с исходной версией подтвердило неизменность определений
`Parser` и моделей структурированного ответа. Лимиты времени и инструментальных
вызовов, однократная перепроверка и отказ от первой догадки при ошибке сохраняются
и проверяются существующими тестами.

Общие команды проверок приведены в
[руководстве разработчика](../development.md#автономные-проверки).

## Выводы и ограничения

Автономные проверки подтверждают исправление обработки ответов API, но не
понимание новых инструкций живой моделью. Платная evaluation, включая новые
сценарии, не запускалась. Частота ошибок модели, расход токенов и задержка не
измерялись; утверждений об их улучшении нет. Разделение промпта по режимам
отложено до отдельного сравнения.

После завершения этого этапа по отдельному запросу пользователя выполнена
[платная evaluation](2026-09-27-live-parser-evaluation.md). Её результаты
записаны отдельно и не относятся к автономному прогону выше.

Актуальные ограничения пользователя описаны в
[руководстве](../usage.md#ограничения), правила проверки источников и запуска
evaluation — в [документации разработчика](../development.md).
